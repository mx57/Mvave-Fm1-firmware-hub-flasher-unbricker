# План реализации: Реальное определение USB OTG, блокировка ложной прошивки и точная диагностика Normal / Soft-Brick / Hard-Brick

## 1. Причина текущей проблемы и цель изменений
В текущей реализации:
1. По умолчанию был включен флаг симуляции (`_useSimulationMode = true`), а метод `refreshUsbConnection()` при отсутствии физических USB-устройств автоматически подставлял виртуальный профиль синтезатора (`sim_mvave_normal_midi`), даже когда пользователь отключал симуляцию.
2. В `UsbFlashEngine.executeFlashPipeline()` при отсутствии открытого физического `UsbDeviceConnection` цикл записи не прерывался ошибкой, а просто пропускал `bulkTransfer()` и возвращал успешный результат.

**Цель**: Полностью исключить ложную «успешную прошивку в пустоту». По умолчанию приложение работает **строго с реальным физическим USB OTG**. Если синтезатор не подключен (или не выдано USB-разрешение Android), кнопки прошивки, чтения бэкапа и авто-восстановления блокируются с четкой индикацией причины, а встроенный аппаратный сканер точно распознает состояние устройства: **Не подключено**, **Штатный режим (Normal MIDI)**, **Soft-Brick (Загрузчик OTA / WL82 UBOOT1.00)** или **Hard-Brick (Поврежден Boot Header `0x0000–0x3FFF` / подключение через программатор RP2040)**.

## 2. Ключевые архитектурные изменения

### А. Честное состояние подключения и BroadcastReceiver USB OTG (`UsbFlashEngine.kt` & `MainActivity.kt`)
- **Новое состояние подключения (`UsbConnectionState`)**:
  - `DISCONNECTED` — по USB OTG ничего не подключено (либо кабель подключен, но чип в состоянии полного Hard-Brick и не отвечает на шине USB).
  - `UNRECOGNIZED_USB_DEVICE` — подключено стороннее USB-устройство, не являющееся M-VAVE FM-1 / SMK-37 / JieLi WL82 / RP2040.
  - `PERMISSION_REQUIRED` — устройство обнаружено на шине USB, но пользователь еще не подтвердил системный диалог доступа Android USB Host.
  - `CONNECTED_NORMAL_MIDI` — синтезатор в рабочем режиме (`VID_4C4A:PID_4155` или USB Audio/MIDI Class с именем порта `FM-1`, `SINCO`, `SLOOP`, `Felucca`, `Clipper`, `JIANT` и т.д.).
  - `CONNECTED_SOFT_BRICK_BOOTLOADER` — синтезатор в режиме загрузчика (`JieLi WL82 UBOOT1.00 VID_4C4A:PID_8057` или OTA MIDI Loader `ota-FM-1_9XX`).
  - `CONNECTED_HARD_BRICK_BRIDGE` — обнаружен аппаратный мост восстановления (`RP2040 / Pi Pico Transporter VID_2E8A:PID_000A` или чип в режиме голого MaskROM без разделов).
  - `SIMULATION_ACTIVE` — учебный/тестовый режим (по умолчанию **ВЫКЛЮЧЕН**, включается только вручную переключателем с явной пометкой `[СИМУЛЯЦИЯ]`).
- **Автоматическое отслеживание событий USB OTG в реальном времени**:
  - Подписка через `BroadcastReceiver` на `UsbManager.ACTION_USB_DEVICE_ATTACHED`, `UsbManager.ACTION_USB_DEVICE_DETACHED` и `ACTION_USB_PERMISSION`, чтобы статус в верхней панели и на экранах «Прошивка» / «Unbricker» мгновенно обновлялся при втыкании или выдергивании OTG-кабеля.

### Б. Глубокая аппаратная диагностика и распознавание Normal / Soft-Brick / Hard-Brick (`UsbFlashEngine.kt`)
- **Многоуровневый анализатор подключенного устройства (`runDeepHardwareDiagnostics()`)**:
  1. Проверка USB-шины Android (`UsbManager.deviceList`): анализ `VendorID`, `ProductID`, `ManufacturerName`, `ProductName`, классов интерфейсов (`USB_CLASS_AUDIO` / `USB_SUBCLASS_MIDISTREAMING`, `USB_CLASS_VENDOR_SPEC`, `USB_CLASS_MASS_STORAGE`, `USB_CLASS_CDC_DATA`) и конечных точек (`Bulk IN/OUT`).
  2. **Активный USB-MIDI SysEx / Bootloader опрос (Probing)**:
     - Открытие физического `UsbDeviceConnection`, отправка запроса идентификации устройства (`F0 00 59 11 ... F7` и Universal Device Inquiry `F0 7E 7F 06 01 F7`) и чтение ответа из `Bulk IN` конечной точки.
     - Если возвращается дескриптор вида `ota-FM-1_9XX` или устройство висит на `VID_4C4A:PID_8057` (`WL82 UBOOT1.00`), диагностируется **Soft-Brick (Сбой раздела приложения `0x4000`, загрузчик цел)**.
     - Если возвращается дескриптор `FM-1_015` / `FM-1_9XX`, диагностируется **Normal Mode (Исправный синтезатор, прошивка `FM-1_XXX`)**.
  3. **Интерактивный детектор Hard-Brick (когда синтезатор физически подключен кабелем OTG, но `deviceList` пуст)**:
     - Если пользователь нажимает «Диагностировать подключение» при физически подключенном кабеле, а на шине USB 0 устройств (или устройство выдает 0 конечных точек / ошибку чтения дескриптора), диагностический модуль проверяет поддержку `android.hardware.usb.host`, питание OTG и определяет состояние **Hard-Brick (Затерт загрузчик `0x0000–0x3FFF`, чип AC791N не инициализирует USB-стек)** с автоматическим переключением на мастер восстановления через **RP2040 / Pi Pico Transporter**.

### В. Строгий контроль физической записи в `executeFlashPipeline()` и `FirmwareHubViewModel.kt`
- **Запрет прошивки без устройства**:
  - Если `connectedDevice == null` (устройство не подключено) и режим симуляции выключен:
    - Кнопка **«Запустить безопасную прошивку»** и кнопка **«1-Click Soft-Brick Recovery»** заблокированы, а при попытке вызова выдается ошибка: *«Синтезатор не подключен по USB OTG! Подключите M-VAVE FM-1 через OTG-кабель.»*
- **Контроль реальной передачи пакетов (`bulkTransfer`)**:
  - В `UsbFlashEngine.executeFlashPipeline()` при работе с реальным устройством (`!deviceInfo.isSimulated`):
    - Обязательно проверяется `usbManager.hasPermission(usbDevice)`, успешное открытие `openDevice(usbDevice)`, `claimInterface(...)` и наличие `Bulk OUT` конечной точки.
    - На каждом секторе проверяется код возврата `connection.bulkTransfer(...)`. Если `transferred < 0` (например, кабель выдернули во время записи или устройство не отвечает), прошивка немедленно прерывается с выбросом исключения `IOException` и отображением реальной ошибки USB I/O вместо ложного сообщения об успехе.

## 3. Изменения в пользовательском интерфейсе (`FlasherScreen.kt`, `UnbrickerScreen.kt`, `MainActivity.kt`)
- **Верхняя панель статуса (Top Bar)**:
  - Если устройство не подключено — красный/янтарный индикатор **«USB OTG: НЕТ УСТРОЙСТВА»** (вместо прежнего зеленого `VID_4C4A:PID_4155`).
  - При подключении реального кабеля — точный статус: **«OTG: FM-1 NORMAL»**, **«OTG: SOFT-BRICK (UBOOT1.00)»** или **«OTG: RP2040 BRIDGE»**.
- **Карточка «Аппаратный детектор состояния» на экранах Прошивки и Unbricker**:
  - Показывает реальный результат сканирования USB-шины, кнопку **«Сканировать USB OTG / Проверить статус кирпича»**, кнопку **«Запросить USB-разрешение»** (если доступ еще не выдан) и интерактивный чек-лист определения **Soft-Brick vs Hard-Brick**.
  - Переключатель **«Тестовая симуляция (без железа)»** по умолчанию выключен (`false`) и снабжен предупреждением, что он предназначен только для ознакомления с интерфейсом.
